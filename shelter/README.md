# 避难所 Playtest · 双网页

《避难所 Playtest 双网页编程说明》（规则快照 2026-10-04）的第一版实现：
**主持人面板** `host.html` 与 **玩家面板** `player.html`，各自独立保存数据。
优先保证是一个可操作的测试工具，不是完整的商业游戏。

- 线上入口：<https://www.xxxmnalx.com/game/shelter>
  （主持人 `/game/shelter/host.html`，玩家 `/game/shelter/player.html`）
- 离线使用：直接双击 `host.html` 或 `player.html`。每个文件都内含全部 CSS、JavaScript 与道具数据，
  不加载 CDN、远程字体，不发任何网络请求。

> 与说明书不同的地方只有一处：按惯例部署到了 Vercel 并挂在 xxxmnalx.com 下。
> 线上版本仍是同样的两个静态文件，不引入账号、服务器、实时同步或远程数据库。

## 动画与音效

- **怎么做到的**：动画层（`src/fx/`）不改页面逻辑。页面每次保存存档时，它对比前后两份存档，知道「刚发生了什么」，等页面画好后给对应元素加动画
  （Web Animations），并播放现场合成的音效（Web Audio，没有音频文件，离线可用）。浏览器要求先点一下页面才允许出声；撤销、导入、重置、切换演示存档不放效果。
- **玩家页**：点亮行动按钮会弹一下并发光；守夜卡牌背朝上发出来再翻面，全员卡翻开后泛橙光，选中的卡跳一下、另一张变淡；
  搜刮每轮选项依次滑入，最后 3 秒倒计时变橙并滴答，选完／超时各有提示音，全部结束有一段完成音；
  生命减少时状态格抖动泛红（回升时发光），饥饿、口渴、意识、负面状态变严重时抖动、好转时发光；新物品弹出来，确认携带时有上锁声。
- **主持人页**（只给公开时刻配声音）：新的一天和换阶段有钟声，阶段轨与大标题滑入；轮换座次时座次依次滑入；
  计时最后 10 秒滴答、最后 3 秒更急，到点响三声并闪烁；公共事件揭晓时事件卡从上方翻下来，投票选项依次出现；
  营救进度上升有上行音阶；新的公开结果滑入。打开玩家的守夜链接时卡片在弹窗里翻出来，但**不出声**（秘密页）。
  屏幕共享时勾选了「共享声音」，大家都能听到这些提示音。
- **设置**：左下角的音符按钮打开面板：动画 跟随系统／开／关，音效 开／关，音量，以及九种音效的试听，本机记住（`shelter-playtest:fx`）。
  默认动画跟随系统、音效开。系统开了「减少动态效果」时只淡入淡出。全屏展示时按钮自动隐藏。

## 中文／English

三个页面（入口、主持人、玩家）右上角都有语言按钮：中文界面显示「EN」，英文界面显示「中文」。选择记在本机浏览器里，三个页面共用，刷新后保持；默认中文。

- **只换显示文字**：所有界面文字在显示时才翻译，存档里的数据（状态值、日志、名字）保持原样，所以切换语言不影响存档、规则判断和撤销，
  中文与英文界面可以随时来回切。已经用中文写下的日志和交接文本在英文界面里会按词典译出显示。
- **演示存档**：在英文界面下打开演示存档，玩家名、事件、笔记等演示内容直接用英文生成。
- **录入物品**：英文界面下批量录入、开局模板等可以写英文名（`Bread×3, Water+2`），中文名和物品 id 也照样能用。
- **复制出去的交接文本**按当前界面语言生成：英文界面复制出的就是英文。
- 浏览器测试会切到英文、打开演示存档，逐页检查主持人与玩家的每个标签页都没有残留中文。

**改了界面文字之后**：运行 `python3 tools/i18n.py missing` 找出没有英文的新字符串，在 `src/shared/i18n/` 对应的 `.tsv` 里补上一行再构建。
拼接出来的句子按片段翻译（引擎会先套「第 N 天」等固定句式，再按词条从长到短替换，最后把全角标点换成半角）；
同一个中文在不同位置意思不同时（如「口渴」既是栏目名「Thirst」又是状态值「Thirsty」），代码里用 `U.TC('label', '口渴')`，词典写 `label|口渴`。

## 主持人操作说明

主持人页优先桌面（主持＋屏幕共享），平板与手机也能用。版面按「谁在看」分三层：

- **顶栏**（每页都在）：天数、阶段、存活、营救进度，「配置未完成 N 项」小标签，以及「回退／下一阶段」「撤销／手动调整」「一键隐藏所有秘密」三组按钮。
- **标签分组**：可以共享的「主持台、公开展示」｜带锁、要先暂停共享的「补给与公共池、守夜、公共事件、记录与结算、日志」｜「设置与存档」。
- **主持台**（默认页，没有秘密）：主持人自己的工作台，从上往下读：
  - 阶段轨：整天流程一行排开，做完的打勾、当前的高亮，点任一阶段可跳转（记入日志，不回滚数据）；
  - 当前阶段卡（主区）：本阶段要做的事和完成度（如「已行动 2／6」），底部有与顶栏相同的「进入下一阶段」按钮，写明要去哪个阶段；
  - 侧栏：**待办**（按严重度排序，图标＋文字＋颜色，点链接直接去处理：未轮换、谁还没行动、批次未领完、守夜名单未确认、
    事件未判定／未公布／未结算、昨夜结果未公布、营救达阈值、死亡玩家仍在座次、配置未完成等）、存活与今日公开结果两张小卡、营救进度、计时、速查；
  - 座次调整与发布公开结果在主区下方。电脑上主区＋侧栏两列；平板与手机变一列，顺序为待办 → 当前阶段 → 概况 → 其余。
- **公开展示**：给 Discord 看的页面。最大的字是当前阶段，下方阶段条显示今天走到哪；主视区随阶段切换——个人行动时大字显示「轮到谁」、
  补给时显示领取顺序、事件时显示正文与投票选项，其余时候显示座次；右侧计时与营救进度，下方公开结果。
  「全屏展示」隐藏主持人工具栏并放大字号，按 Esc 或「退出展示」恢复。

**屏幕共享规则**

- 「主持台」和「公开展示」都可以直接共享；给玩家看时用公开展示的「全屏展示」。待办与概况只用公开信息（人名、件数、份数），不带物品、候选或事件内容。
- 带锁的标签页（补给与公共池、守夜、事件结算与事件库、分数与私信、完整日志）默认**不渲染**内容——不是模糊或蒙层，
  所以悬浮、页面搜索、通知、日志摘要都拿不到。点「显示…」时必须勾选「我已暂停／切换屏幕共享」。
- 刷新页面后一律恢复隐藏。网站无法替 Discord 隐藏已经共享出去的画面：选物资、私发候选前请先暂停共享。

**每日流程**

1. **开局准备**：在「设置与存档」登记玩家（每人有稳定 ID，座位号不是身份），在「补给与公共池 → 开局物资」设计开局模板。
   两次开局领取可以走公共池抽取，也可以「固定指定」直接生成每人的交接文本。不会自动设定任何配比或默认套装。
2. **阶段1 昨夜结果**：公布前一晚保存的守夜结果（首日可直接跳过）；营救进度在「主持台」侧栏修改。
3. **阶段2 资源补给**：「新建发放批次」按参与人数 N 从公共池**实际件数**中无放回抽 N 件，抽到即从池中扣除并存档（刷新不重抽）。
   按座次逐人「记录选择」，被选走的物品从候选移除；每次选择都会弹出交接文本，玩家自己加进库存。
   「撤销整个批次」会把物品原样归还公共池，并列出需要手动撤销的已领取者。公共池不足时不会生成不存在的物资。
4. **阶段3 自由交流**：讨论、交易、赠予、预先协商换位都不收费（交易双方各自在玩家页增减）。
5. **阶段4 每日轮换**：末位移到首位，每天只执行一次；跳过时会询问并记入日志。
6. **阶段5 个人行动**：进入时把座次复制为本轮固定的 `actionOrder`。逐人「记录行动」：
   计划守夜名单（候选卡由玩家在自己的页面抽，见阶段6）、使用技能、其他、放弃。「换位请求」只改实际座次，不改本轮行动顺序；
   每人最多3次请求（可覆盖），失败是否仍耗行动、被请求者是否支付行动都由主持人当场选择，不自动扣除。
7. **阶段6 确认守夜**——玩家抽卡、选卡、发一条链接，主持人点开就进候选池：
   - **玩家抽卡**：只有当玩家在「行动与身份」页点亮「计划守夜名单」时，下面才出现「守夜名单」。点「确认抽取守夜名单」随机生成两张卡，
     选一张，复制分享链接发给主持人，不需要其他操作。卡片从玩家自己录入的完整名单里抽人（存档页「玩家名单」：本人名字＋其他玩家的名字）。
     同一玩家同一天抽到的两张卡固定（按玩家＋天数＋名单定种子），取消行动再点亮也不会重抽。
   - **卡面**（每张卡独立随机）：
     - **10%** 是全员守夜卡：整张卡只写「所有人需要进行守夜」，没有名字、图标或其他文字；
     - 否则卡片中央是**不重复的必定守夜人名**，人数＝玩家总数的三分之一、向上取整（6人2人、7人3人；规则里可固定人数）；
       左下角 **33%** 出现「今天使用技能的人需要守夜」图标，右下角独立 **33%** 出现「今天计划守夜名单的人需要守夜」图标；
       正上方 **25%** 随机出现一句：「似乎今晚守夜的人会有更多危险」或「似乎今晚守夜的人会有更多求救线索」。
   - **分享链接**：`host.html#watch=…`，带着已选卡片的完整结果（约 200～300 个字符）。主持人点开后先确认已暂停屏幕共享才显示卡面，
     看到的和玩家选中的一模一样，不重新随机；名字自动对上主持人端的玩家（对不上的会列出来），确认后加入当天的候选池
     （主持人还没在行动表里记这名玩家时会顺便补记）。链接在别的设备上打开时，也可以粘贴到「守夜」页的输入框。
     同一浏览器里已经开着的主持人标签页会自动重新载入存档，不会提示冲突。玩家没法用页面时，主持人可以「代抽两张」（同样的规则）。
   - **0 份**：系统按同样的规则随机一张；**1 份**：直接成为最终名单；**2 份及以上**：复制给末位的私信（列出各份名单），
     实际换位后座次最后的玩家回复编号，主持人点「末位选第 N 份」。只负责拍板的末位不算计划者，除非他自己也用行动计划过名单。
   - **确认人员**：卡上的名字＋图标点到的人（按当天的行动记录）＝预选人员；全员卡＝所有存活玩家；主持人可以增减。
     确认时保存人员快照，是否公开由主持人决定。卡片只负责抽取、选择与分享，夜间后果仍由结果库按权重抽或手动选（倾向句决定筛选哪类结果），保存后**次日阶段1公布**。
8. **公共事件**：位置可在规则里设为阶段2之前或阶段6之后；未设置时随时手动触发。
   每日判定一次（80%触发），只决定是否触发；选事件 → 公布正文 → 录入 Discord 投票 → 按该选项的结果概率抽签（合计100%才能自动抽签，否则手动指定）
   → 预览效果 → 确认结算。一次确认产生唯一的 `resolutionId`，重复点击不会重复加营救或补给；可精确撤销。
   公共池不够扣时结算会暂停，由主持人修改效果或覆盖，不会扣成负数。个人效果只生成通知文本。
   - **随机抽取事件**（「公共事件」页的秘密区，主持台的事件阶段有入口）：点「随机抽取一件」，从事件库里等概率抽一件。
     默认只抽正式与演示事件（可勾「草案也参与」），并且**不重复**——跳过本局已经用过的事件（以前各天的事件流程、今天的流程、未撤销的结算），
     全都用过时会提示并退回全部候选；有标签或地点时可以只抽某一类；没有投票选项的事件不参与。
     抽到的结果先存档（刷新不变），只在秘密区显示：看过再点「使用这件」进入上面的结算流程，或「重抽」（这次不会再抽到刚才那件；次数记入日志与事件来源）。
     抽取时名字会在候选之间翻动后停下（动画，不出声）。也可以照旧手动选择或临时录入。
9. **进入下一天**：当日计划者、技能使用者、候选等归档并清空；跨日回退会恢复前一天的记录与座次。

**记录与结算**：营救阈值未知，不会自动结束。玩家上报的财富（钞票×1＋名画×6＋珠宝查表）、地图分、爱恨分、生存分、任务分、裁定调整逐项录入；
留空就是「待定」，合计显示为「部分分数／待裁定」，不会显示成完整的最终排名。

## 玩家操作说明

玩家页手机优先：手机上导航在底部（总览、状态、库存、搜刮、行动常驻，分数与存档在「更多」里），平板为顶部标签，电脑为左侧导航栏加多列内容。
「携带」已并入库存页、「身份」已并入行动页，上次停在旧页的会自动转到新页。
顶部常驻名字、「第几天」与撤销；除总览页外还有一排**简要面板**：生命、饥饿、口渴、意识、库存、负面状态（携带中时换成携带占位），
每格有名称、大号数值和小进度条，注意／危险时整格变橙／变红，点一下去对应页（电脑 6 格一行，手机 3×2）。手机上顶栏随页面滚走，不占屏幕。

- **总览**（默认页）：一眼看清最重要的信息——
  生命（大号数字；生命上限未配置时一格一点，不暗示上限）、饥饿、口渴（三档分级条）、意识、库存占位（进度条）、财富估算、今天是否已行动；
  「需要留意」按严重程度汇总已记录的事实（生命为0、脱水／昏迷、流血到期、超容量、携带超限、搜刮进行中、今日行动未标记），每条可一键跳到处理页；
  「进行中」列出携带、搜刮与临时效果；「占位构成」用单色条形图按分类显示占了多少单位；另有负面状态、身份与目标（可在本机遮住）、最近记录与常用快捷操作。
  状态一律用「图标形状＋文字＋颜色」表示，不只靠颜色（橙色与红色在色觉差异下难以区分）。

- **状态**：生命初始5，基础战斗力＝当前生命；饥饿是数值，阈值未配置时手动选「充盈／普通／饥饿／饥荒」（新玩家默认普通；饥荒比饥饿更严重，提醒为危险，后果待主持人裁定；
  填了「饥荒阈值」才会自动判为饥荒）；口渴三档，脱水直接昏迷；
  不会自动把0生命或昏迷判成死亡。流血伤口记录获得日与下次触发日，到期只提醒，与主持人确认后再扣血。
- **库存与携带**：物品是一张张长方形卡片，顶边颜色表示类别（颜色只是辅助，类别名始终写出来）；「排列」可选**按类别**（补给／医疗／财富／装备／特殊／自定义分区，各区显示件数与占位）
  或**默认顺序**（获得的先后），选择记在本机；类别筛选、总占位／10单位（超出只警告）。每张卡片有「使用／赠予／修改／删除」，**删除**为红色，可选数量、可撤销，
  不生成交接文本（交给别人请用赠予）。能量棒、地图、水壶、背心按实例保存剩余次数、笔记、水量、完好／破损，
  不同实例不会合并。「使用」只对已确认的效果提供快捷操作（绷带恢复1生命或止血、地图加1笔记……）；恢复量未定的食物需要手动填写，留空就不改。
  子弹、跳棋、信号枪等用「记录使用」，默认不扣数量。所有常规消耗都可撤销。
- **赠予／交公／治疗他人**：从自己的库存扣除并生成交接文本，由对方或主持人手动修改。
- **携带模式**（在库存页）：选事件或守夜，上限默认 **2 单位**（规则里填了事件／守夜上限就用规则，也可当场改）→ 在卡片上点「带上」挑选，超出上限的选不上
  → 「确认携带」后只有带上的卡片高亮可操作，其他物品暂时锁定 → 主持人宣布结果后直接在高亮卡片上删除或修改 → 「结束携带」解锁。
  携带只引用库存实例，不复制物品；面板上显示已选占位与战斗力（多武器是否叠加未定时同时列出两种算法）。手机上携带面板贴在底栏上方，翻到哪都能确认。
- **搜刮**：主持人通知后手动开始，3轮×3选项×7秒，每组 1.5～2 单位，超时自动选标明的默认项。
  补给之外的物品每组最多一件，同一组里已有同类（补给除外）时再出同类的概率降到 1/5（「武器＋武器」很少见）；
  示例模板里能量棒、奶油汤和装备的权重明显低于面包、普通水（抽 5000 组：面包、普通水各约 31%，能量棒、奶油汤各约 12%，消防斧约 4%，步枪约 2%）。计时按截止时间计算、候选与选择立即存档，
  刷新或切到后台都不会多领一轮。完成后自留不超过4单位、总库存另算10单位，其余形成交公清单，预览后一次性提交。
- **守夜名单**（行动与身份页）：只在今天的行动点亮「计划守夜名单」时出现。点「确认抽取守夜名单」得到两张卡，选一张，
  复制分享链接发给主持人即可。卡上的名字来自存档页的「玩家名单」：在那里录入其他玩家的名字（多个用逗号分开），与你自己的名字组成完整名单；
  导入主持人的规则包也会自动填好。卡面规则见主持人说明的阶段6。
- **行动与身份**：今天的行动是一排按钮——计划守夜名单、尝试换位、使用职业技能、其他行动、放弃行动；点一个点亮＝记为今天的行动，再点取消，点别的就改选
  （只记在自己页面，不与主持人同步）。「职业技能」单独一张卡：选职业、看技能说明与使用记录；点亮「使用职业技能」时自动记一条使用记录。
  同页还有身份与秘密（姓名、爱的人、恨的人，可以是自己）、秘密任务（开关启用后可选）和制作进度。
- **分数**：财富估算、地图笔记、任务进度与手动分数，可一键生成上报文本。

## 存档

- 两端自动保存到浏览器 `localStorage`，命名空间不同：
  主持人 `shelter-playtest:host:v1`，玩家 `shelter-playtest:player:v1`；演示存档另用 `…-demo:v1`，载入或清空都不会碰到正式存档。
- 支持 JSON 导出、复制、文件导入、粘贴导入、重置与「撤销最近操作」。导入前会校验结构并先备份旧存档（保留最近5份），导入失败不会改动当前存档。
- 浏览器本地保存不可用（隐私模式等）时会显示红色提示，页面仍可在内存中运行并导出文件。
- 主持人可以导出「规则包」（规则配置＋自定义物品＋玩家名单），玩家在自己的「存档」页导入。
- **一键重置**：主持人页、玩家页的「存档」里各有一个，删除这个浏览器里本页的全部数据（正式存档、演示存档、备份、页面设置）后，
  带着新的地址参数重新载入，避开旧缓存；另一页的数据和语言选择不受影响。入口页底部的「一键重置本机数据」会把两页的数据一起清掉。

## 事件导入格式

事件库支持导入导出 JSON（`{ "kind": "shelter-events", "schemaVersion": 1, "events": [...] }` 或直接一个事件数组）。
每个事件：`name`、`body`、`location`、`tags`、`isDraft`、`participants`、`carryTicks`（半格计，2 = 1单位）、`conditions`、`itemUses`、`modifiers`，
以及 `options[].label` 与 `options[].outcomes[]`（`text`、`probability`、`effects`）。
`effects` 包含 `rescue`（营救±）、`pool`（`[{defId, qty}]`，负数为扣除）与 `personal`（`target`、`hp`、`hunger`、`thirst`、`status`、`items`、`mapNotes`、`note`，只生成通知）。
正式库默认为空；页面里附两个明确标记为【演示】的模板。

## 实现建议与假设（不是新增规则）

- 容量以半格整数 ticks 保存（1 tick = 0.5 单位）。
- 每日发放默认每件等概率，可在「抽取权重」里改。
- 搜刮候选从玩家页可编辑的搜刮模板生成（示例模板包含全部内置物品，权重见上），不扣公共池；每组在「上限−0.5」到上限之间（默认 1.5～2 单位），不会超出。
- 规则第2版：旧存档里仍是旧默认值（5秒、约3单位）的搜刮设置会自动改成 7 秒、2 单位，手动改过的保留；没改过的示例搜刮模板换成新权重，自定义模板保留。
- 搜刮超时的下一轮从上一轮截止时刻起算；页面关闭期间到期的回合全部按默认项记录。
- 医疗箱对自己使用时，默认只勾选已确认属于伤病类的状态（流血伤口）；草案状态是否属于伤病类由主持人裁定。
- 夜间结果按名单的风险倾向筛选结果库（没有倾向时取中性结果），权重全部填写才允许自动抽取。
- 演示存档里的六位玩家、物资、两个事件和三条夜间结果都标有「演示」，只为走通流程。

cd shelter
node build.mjs            # 修改 src/ 后重新生成 host.html、player.html
node build.mjs --check    # 检查产物是否与源码一致
python3 tools/i18n.py missing             # 列出还没有英文的界面文字
node --test tests/core.test.mjs          # 单元测试（无依赖）
npm install && npm run test:e2e          # 浏览器验收（需要 Playwright 的 Chromium）

`src/`、`tests/`、`tools/` 与构建脚本由根目录的 `.vercelignore` 排除，不会被公开。

与主站同 origin，因此存档在 `www.xxxmnalx.com` 下保存；直接访问 `*.vercel.app` 时页面会提示两处存档不互通。
